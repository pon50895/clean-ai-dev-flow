# 派工 brief 固定紀律段

> **每份派給 subagent 的 brief 必含。** 整段複製進 brief,依情境刪不適用的行,把 `<...>` 換成實際值。
>
> **這個檔為什麼存在**:某次派工的 brief 寫了「禁止碰 prod」「不要跑全套測試」「不要碰主樹」——
> 就是**漏了「rm 是使用者地盤」**。agent 跑了 `rm`、撞 guard、使用者被彈窗。
> 那條紀律從來沒進過任何範本,每次靠指揮官當下想起來,而那次沒想起來。
>
> 更早之前,同一件事已經被提過一次(「派工 brief 加固定紀律段」),寫進檢討報告就沒下文了 ——
> **沒有 owner 的 prose 會蒸發**。所以本檔配一支 hook(見底部),缺紀律段就擋。

---

## 複製這段

```markdown
## 工作區與紀律(嚴格)

**工作區**
- 你的 worktree:`<PATH>`,branch `<BRANCH>`,已從 `<BASE_REF>`(`<SHA>`)拉好。**只在這個路徑工作。**
- **禁止碰主工作樹** `<MAIN_TREE_PATH>` —— 使用者可能有未提交改動 / 它可能停在舊 SHA。
- **禁止碰其他 worktree** —— 同時可能有別的 agent 在跑。跨 worktree 讀取用 `git show <ref>:<path>`。

**破壞性操作(guard 會擋,別請求使用者放行)**
- **禁 `rm`** —— rm 是使用者地盤,AI 一律不執行。暫存檔放 `<SCRATCH_DIR>`(已豁免);
  mac 的 `sed -i ''` 不產生 `.bak`,不需要刪。要使用者刪東西 → **列清單給他**,不要自己跑。
- **禁 `git stash`** —— 多個 worktree 共用同一個 `.git`,stash 會跨 worktree 交叉污染。
- **禁 `git reset --hard` / `git clean -f` / `git checkout --`** 收拾非自身改動。
- **禁 `git push --force`** / `--no-verify` / 任何跳過 hook 的旗標。
- **補 commit 不用 `--amend`** —— push 過就一律補新 commit(amend + force-push 會炸掉 review,
  而且會逼使用者按一次危險確認)。

**測試**
- **只跑受影響的單檔**,不要跑全套(<你的專案的實際限制,例:全套會 OOM / 要 20 分鐘 / 撞共用 DB>)。
- **跑測試前確認沒有其他測試在跑** —— 若共用 test DB,並行會造成兩邊大量假紅。
  真實案例:同時跑兩份 -> FAIL 從 3 漲到 40,兩份數據全廢,而且是「看起來像 regression」的那種廢。
- **輸出一律寫檔再讀**:`cmd > /tmp/x.log 2>&1; code=$?` —— **不要 `| tail`**。
  pipe 會吃掉 exit code(`$?` 變成 tail 的)和輸出(只剩尾巴,看不到真正的錯誤)。

**production / 正式環境**
- **禁止對 prod 做任何寫入。** 唯讀查證可以(`<你的唯讀查證指令範例>`)。
- **prod DB 只能 SELECT。** 不要 dump 個資,只取聚合與必要欄位。
- **禁止動 `.env` / secrets**(使用者地盤)。讀取查證可以,不要印出值。

**紅線**
- **不得有 emoji**(code / 註釋 / commit message / 回報)<若你的專案有這條>。
- 精確 Edit 不全檔覆寫 / 不提交編不過的 code / 不跳過 git hook。
- <你的專案的其他硬性規則,例:i18n 雙語、a11y、theme token>

**調查紀律**
- **每個判定追到根,列出你查了哪些層才敢下判定。** 只看一個檔的判定不合格。
- **不信 client 端的 interface / 型別宣告 / 註解就下跨層結論** —— 去查真正的來源
  (API 的 response model、引擎的實際輸出、DB 的實際資料)。
  真實案例:某 agent 看了前端 interface 說「這個欄位不存在」,實際上後端一直有回傳,
  只是前端沒宣告 —— 結果它去擴充了一個根本不需要擴充的資料結構。
- **陽性對照鐵律**:任何「不存在 / 沒觸發 / 沒有 X」的斷語,
  **必須先用同一方法驗一個已知存在的 X**,證明你的方法測得出來。做不到 → 標「未驗」。
- **沒跑完不報數字** —— 測試跑到一半的 FAIL 數不是結果。
- 拿不準標「需使用者決定」,不要硬給。

**完成的定義**
- commit + push 到自己的 branch。**不動其他 worktree 的任何狀態。**
- **不要開 PR**(指揮官開)。
- 回報附**實際輸出**(測試 / build / typecheck),沒有證據的「通過」視同未驗。
- **驗不到就說驗不到,不要美化。**
```

## 為什麼需要配一支 hook

本檔是**規則**(靠指揮官記得複製它)。規則會在壓力下被跳過 —— 這個檔本身就是「上次的規則被跳過」的產物。

配套:`.claude/hooks/agent-brief-guard.js` 攔 `Agent` tool 的 PreToolUse,偵測 prompt 有寫入意圖
(提到 worktree / commit / push / 實作)但缺 `## 工作區與紀律` 這個 heading → **deny**。
deny 彈回模型自己補,**使用者零彈窗**。唯讀 agent(Explore / 稽核 / 查證)一律放行,不製造摩擦。

**失效判據**(寫在這裡,讓下次驗收的人能直接判):再次出現「brief 漏寫某條紀律 → agent 撞 guard →
使用者被彈窗」。若 hook 生效,這件事應該變成「agent 根本沒被 spawn,指揮官自己補完再派」。

**判準**:能用機器擋的就不要靠人記得。這個檔的價值不在它被讀,在它被 hook 逼著複製。

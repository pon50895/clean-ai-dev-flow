# social-media — 社群內容

改造自 coreyhaines31/marketingskills 的 `social`(MIT license)。平台聚焦台灣常用的 **FB / IG / Threads**(原版的 LinkedIn/X/TikTok 換掉);砍掉 A-B 測試與大規模投放段(YAGNI)。開工前讀專案自己的 product-marketing context 文件(品牌語氣、customer language),沒有先跑 `product-marketing`。

## 開工前先問

目標(獲客 / 導流 / 品牌)、目標受眾、要發哪個平台、有沒有現成素材可再利用(更新日誌 / 報告 / 免費工具)。

## Hook — 第一行決定有沒有人往下看

四類 hook,都守**不恐嚇**:

- **好奇型**:點出一個大家以為如此、其實不然的事(不製造恐懼)。
- **故事型**:真實情境開場,不喊「震驚」。
- **價值型**:「三個判斷 X 的方法」,直接給乾貨。
- **反直覺型**:把產品定位講成一句有張力的話,當鉤子。

禁:恐嚇式(「不看會出事」)、宿命論斷言、AI 腔(空洞抒情句)。

## 內容支柱(3-5 個,對齊定位文件)

例:(1) 領域知識科普(去神秘化、講原理);(2) 建造日誌 / 產品思路(不推銷);(3) 免費工具導流;(4) 客戶語言回應(把 customer language 變成貼文主題)。每篇歸到一個支柱,別亂發。

## 內容再利用

- **更新日誌 -> 社群三平台**:一份日誌拆成 FB / IG / Threads 三種長度。
- **使用洞見 -> 貼文**:把一個具體洞見拆成單篇(不洩個資、不宣稱療效或保證)。
- **免費工具 -> showcase 貼文**:工具的一次具體結果當鉤子。

## 短影音腳本(IG Reels / Threads)

結構:痛點 -> 一個具體解法 -> 導流。前 3 秒定生死。守專案內容紅線:不做確定性斷言、不碰財務 / 健康 / 生命的保證。

## 平台差異(台灣)

- **Threads**:短、對話感、可連發串。台灣口語,別官腔。
- **IG**:圖卡 + 短 caption,Reels 走短影音。
- **FB**:可長一點,社團導流。

## 對外文案紅線(每篇都套)

- 供應商保密規則依專案政策。
- 不宣稱未發生的驗證 / 審核 / 保證;不寫死價錢。
- 台灣式、去中國用語、去 AI 腔(去對稱排比空洞金句)。

## 收尾

每篇定稿前過 `de-ai-tone`(潤成台灣人講話)+ 專案自己的 claim 逐條查證流程(任一不實即阻斷)。

# free-tools-growth — 免費工具獲客

改造自 coreyhaines31/marketingskills 的 `free-tools`(MIT license)。核心差異:重點不是「該不該蓋工具」,而是「先把現有免費工具接成獲客迴圈,只在有明確缺口時才蓋新的」。原版評分表保留;付費廣告 / 大規模那段砍掉(YAGNI,早期口碑階段用不到)。

開工前先讀專案自己的 product-marketing context 文件(沒有先跑 `product-marketing`)。

## 先盤點現有免費工具

列一張表再說要蓋新的:

| 工具 | 入口在哪 | 有沒有 lead capture | 有沒有歸屬參數 | 導向下一步 |
|---|---|---|---|---|
| (專案自填) | | | | |

**先問**:現有工具的獲客漏斗接好了嗎(入口曝光、歸屬追蹤、導向下一步)?通常補現有工具的轉換比蓋新工具槓桿高。

## 三個核心原則

1. **解真問題**:工具本身要有用,不靠主產品也值得用一次。
2. **鄰近主產品**:自然把人從「查一下」帶到「想買完整版 / 預約」。成敗看專案定位文件定義的北極星指標,不是工具使用數。
3. **一件事做好、低摩擦**:免登入能玩就免登入,email 才 gate 完整結果。

## 導流路徑(工具 -> 產品)

- 工具給即時免費價值 -> 露出「看完整版 / 個人化結果」-> email 領取 -> 導向預約 / 付費。
- **歸屬參數**(例如 `?ref`)新工具一律帶,能追到是哪個工具 / 哪個分享來的。
- 免費層永遠留一個「往下走」的鉤子,但**不用恐懼式 gate**(「不解鎖就有壞事」)。

## Lead capture 分層

| 做法 | 用在哪 |
|---|---|
| 完全免登入 | 純 SEO / 病毒型工具 |
| 部分 gate(免費看摘要,email 領完整) | 有個人化結果的工具 |
| email 領永久頁 | 內容嚴格本人、需要保存的結果 |

最佳實踐:價值交換講清楚、只要 email、先給 preview。**文案守專案紅線**(見 `product-marketing`):不寫死價錢、不宣稱未做過的驗證。

## 要不要蓋新工具:評分表(1-5 分,原版保留)

| 因子 | 分數 |
|---|---|
| 有搜尋 / 分享需求 | ___ |
| 受眾對得上潛在客戶 | ___ |
| 比現有選項獨特(護城河) | ___ |
| 自然通往主產品 | ___ |
| 建置可行(MVP 能收斂) | ___ |
| 維護負擔(反向計分) | ___ |
| 病毒 / 分享潛力 | ___ |

25+ 強候選 / 15-24 可考慮 / <15 重新想。**低於門檻就別蓋**——早期階段先把現有工具的漏斗榨乾。

## MVP 範圍(YAGNI)

只做核心功能 + 基本 email 收集。跳過:帳號系統、存結果、完美設計、每個 edge case。大型素材不進 git(丟物件儲存、repo 只存 URL)。

## 收尾

工具的對外文案(landing、CTA、email)定稿前過 `de-ai-tone` + 專案自己的 claim 逐條查證流程。跟 `social-media`(把工具做成種子貼文)、`referral-programs`(工具本身當分享標的)串起來用。

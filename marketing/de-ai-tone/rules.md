# de-ai-tone 規則全集

SKILL.md 的完整規則層。改寫時按需讀這份;每條附「前 → 後」示範,範例用通用產品文案語境。

> 分類學(層 0-3、層 6-7 的骨架)借自 kevintsai1202/Humanizer-zh-TW(MIT)→ blader/humanizer(MIT)→ Wikipedia "Signs of AI writing"(CC BY-SA)。層 4(歐化中文)、層 5(標點排版)與各條的「補強」段落來自 2026-07-26 的台灣中文語感調研(下稱「調研」),本檔只留可執行的規則本體。

**信心標記說明**:每條後標〔高〕〔中〕〔低〕。〔高〕=官方規範/學術論文/辭典佐證;〔中〕=媒體報導或社群共識(有樣本但非嚴謹統計);〔低〕=憑觀察無來源,可用但不當鐵律,拿不準時人工裁量優先。標〔機掃〕的規則可以 grep 或未來寫成 hook 做機械檢查。

## 層 0 — 絕對紅線(改寫前先立)

**0a 不捏造事實。**〔高,原有〕 具體化只能用原文或 user 已給的事實;缺料就留 `[需補:一個具體例子]` 佔位,絕不編。真偽查證另走 claim 逐條查證流程,本 skill 只管語感。
- 前:「我們的產品深受用戶信賴。」
- 後(缺料):「[需補:一個具體的用戶回饋或使用數字]」——不要自己編出「上千位用戶好評」。

**0b 法遵不潤、無 emoji。**〔高,原有〕 法律條款、免責聲明照抄原文,不加語氣、不改字。全程無 emoji(R1)。

**0c 標點 house style 是硬規則,不是建議。**〔高,新增〕 中文散文與對外文案一律全形標點,細節見層 5;程式碼/CSS/網址/檔案路徑/指令/JSON 設定檔不適用,改了會壞東西。

## 層 1 — 句式手術(結構性 AI tell)

**1a 對稱排比三連。**〔中,原有〕「有 X、有 Y、有 Z」湊數 → 挑最準的一個。
- 前:「有溫度、有深度、有態度的服務。」
- 後:「講清楚一件事就好:結果準不準,你看得到推理過程。」

**1b 「不是 X,而是 Y」/「不僅…更是…」反義句。**〔中,原有,2026 台灣社群票選 AI 文特徵第二名〕 AI 靠否定墊洞見 → 直接講 Y。
- 前:「這不只是一個工具,更是一場理解自己的旅程。」
- 後:「用完你會知道自己為什麼老卡在同一個地方。」

**1c 句尾補刀分析(中文 -ing)。**〔中,原有〕「…,象徵著/展現了/反映了…」 → 句號就是句號。
- 前:「我們採用 PostgreSQL,展現了對穩定的重視。」
- 後:「我們用 PostgreSQL。」

**1d 繫詞迴避。**〔中,原有〕「作為/充當/設有/擁有一個」 → 直接「是/有」。
- 前:「本平台作為連接賣家與買家的橋樑。」
- 後:「這是一個賣家接案平台。」

**1e 三段式硬湊。**〔中,原有〕 硬湊三項 → 挑一個最真的,或改兩、四項。
- 前:「快速、準確、貼心。」
- 後:「結果準,而且你看得到怎麼推出來的。」

**1f 虛假範圍。**〔中,原有〕「從 X 到 Y」但 X/Y 不同量尺 → 改列舉。
- 前:「從長期規劃到今天的待辦,一手掌握。」
- 後:「可以看整季規劃,也可以看單一決策。」

**1g 同義詞循環。**〔中,原有〕 同一個東西全文叫同一個名字,不輪替「平台/系統/服務/產品」。
- 前:「這個平台…這套系統…我們的服務…本產品…」
- 後:全部叫「平台」(或全部叫產品名),選一個。

**1h 每段金句化 + 破折號濫用,依場景分級。**〔中,補強:調研顯示破折號敏感度已到「看到即判 AI」,原「一篇最多一處」對社群文太寬〕 話講完就停;**社群貼文破折號歸零,長文(建造日誌/報告)全篇最多一處**。
- 前:「這就是我們的堅持——用專業,守護你的每一次選擇。」
- 後:「所以我們把界線先講清楚。」

**1i 「首先…其次…最後」標示性結構(社群文/敘事文專用)。**〔中,新增,調研 A7〕 社群文與建造日誌不用條列標示語 → 照事情發生的順序講,連接詞用「然後」「結果」「後來」。條列留給規格類內容(API 參數、價目表)。
- 前:「首先我們重構了引擎,其次修好了快取,最後上線。」
- 後:「先把引擎拆掉重寫,然後才發現真正的坑在快取,修完才敢上線。」

## 層 2 — 詞彙手術(詞表可機掃)

**2a 空洞大詞黑名單。**〔中,原有 + 補強〕 賦能、擁抱、旅程、溫度、陪伴、療癒、能量流動、深耕、佈局(抽象)、織錦、賽道 → 換具體的事。
對外文案加嚴禁用:**接住、讀懂**;補**穩、撐、懂你**這類雞湯肯定詞〔中,調研 B2:中時報導點名 AI 偏好「穩、撐、懂」,「你不是不努力,只是一直在撐」是典型 AI 心靈雞湯模板,對外文案是重災區〕 → 講資料推出來的具體結論。
- 前:「你一直在撐,我們都懂。」
- 後:「你這兩季的轉換率掉了一成,卡住不是錯覺。」

**2b 中國用語黑名單,分兩級(機掃)。**〔補強:調研指出原表是平面清單,「落地」判過嚴,分級可避免矯枉過正〕

一級:一眼露餡,對外文案零容忍,逐字機掃〔高,教育部/中華語文知識庫佐證〕:

| 中國用語 | 台灣說法 |
|---|---|
| 視頻 | 影片 |
| 質量 | 品質 |
| 信息 | 資訊 |
| 屏幕 | 螢幕 |
| 高清 | 高畫質 |
| 軟件 / 硬件 | 軟體 / 硬體 |
| 默認 | 預設 |
| 網絡 | 網路 |
| 打印 | 列印 |
| 鼠標 | 滑鼠 |
| 服務器 | 伺服器 |
| 程序(軟體義) | 程式 |
| 界面 | 介面 |
| 智能(AI 義) | 智慧 |
| 立馬 | 馬上 / 立刻 |
| 閉環 / 抓手 / 顆粒度 / 對齊(動詞) | 重寫整句 |

二級:有點怪但可接受,長文避免、社群文可裁量〔中低,調研分級多憑觀察,拿不準時人工判斷〕:

| 中國用語 | 台灣說法 | 備註 |
|---|---|---|
| 大概率 | 八成 / 很可能 | |
| 水平(能力義) | 水準 / 程度 | |
| 靠譜 | 可靠 / 穩 | |
| 顏值 | 好看 / 外型 | 已大幅在地化 |
| 落地 | 做出來 / 上線 | 台灣新創圈已通用,判定比舊版寬,**不再列一級** |
| 體驗感 | 用起來的感覺 | |
| 優化(濫用) | 改好 / 修掉 | **只砍當萬能動詞用的情況;技術語境(「優化查詢效能」)合法不用改** |
| 接地氣 | 重寫整句 | |
| 佛系 / 躺平 / 學霸 | 可用,不必改 | 已在地化,列此避免過度矯正 |

**2c AI 高頻連接詞。**〔中,原有〕 此外、值得一提的是、總的來說、與此同時、綜上所述、在這個…的時代 → 刪,直接講下一句。

**2d 宣傳腔形容詞。**〔中,原有〕 坐落於、令人讚嘆、無縫、直觀、強大、充滿活力 → 換成一件做了什麼的事。
- 前:「強大而直觀的報表引擎。」
- 後:「匯入資料,三秒出表,計算每一步都攤開。」

**2e 模糊歸因。**〔高,原有〕「許多用戶回饋 / 專家認為」 → 真有就寫具體那件事,沒有就刪(配合 0a 不許編)。對外文案這條同時是法遵問題(不實宣稱)。
- 前:「許多用戶回饋很準。」
- 後(有事實):「上週一個客人試用完基本版,回頭加購了進階版。」/(沒有)刪掉。

**2f 聊天殘渣 / 免責殘渣。**〔中,原有〕「希望這對您有幫助」「截至目前的資訊」「如有需要請告訴我」 → 刪。

## 層 3 — 台灣節奏(我們的主場,最容易被 AI 磨平)

**3a 長短句交錯,該短就四個字;但均質短句連發是新的 AI 指紋。**〔中,補強:調研 A6 指出全篇短句齊發已成新指紋,原版只教「交錯」缺上限〕 一段最多兩個連續短句,不然又變成另一種模板。
- 前(仍是 tell):「上線了。很快。很穩。值得。」
- 後:「上線了。拖了三週,但值得。」

**3b 保留口語粒子(適量),但「其實」開頭 + 空話是頭號 AI 特徵。**〔補強:調研 A3,2026 台灣社群票選 AI 文特徵第一名——「其實」開頭 + 不談細節只談整體 + 「趨勢/關鍵/必然」〕
- **句中口語的「其實」可留**:「其實這功能我本來不想做。」——這是台灣自然語感,不砍。
- **句首「其實,」+ 空洞宏觀斷言必砍**:整句刪,或砍掉「其實」直接講具體的事。
- 前(必砍):「其實,產品的本質是一場自我對話。」
- 後:(刪。直接講這次改了什麼具體的事。)
- 其餘保留粒子不變:就、反正、蠻、欸。

**3c 斷語 > 機制。**〔中,原有〕 講結論,不描述系統怎麼運作。
- 前:「透過多維度的交互分析,系統能夠推算出您的營收走勢。」
- 後:「你這兩季營收走弱,卡在退貨率上升。」

**3d 念一遍測試。**〔低,原有,無法機掃只能人工〕 像不像會跟朋友講的話;像簡報或廣告詞就重來。

**3e 第一人稱=老闆真聲音,不用「我們致力於」。**〔中,原有〕
- 前:「我們團隊秉持匠人精神,致力打造最好的體驗。」
- 後:「這頁我改了四版,前三版自己看了都想關掉。」

## 層 4 — 歐化中文手術(新增層;AI 中文與翻譯腔的共同病灶)

這層治的是「AI 語法」而非「AI 修辭」——AI 訓練語料裡歐化中文占比高,砍掉這些,文字會同時更中文、也更不像 AI。骨架借自余光中〈怎樣改進英式中文?〉(1987)與後續學術整理,非本調研原創,但把它接進 skill 是本次新增。

**4a 弱動詞「進行」「作出/做出」。**〔高,余光中/學術論文〕「進行」「作出」是萬能動詞,架空真動詞 → 還原真動詞。半機掃:grep「進行」「做出」「作出」逐一人判(有些是合法搭配如「進行式」)。
- 前:「對報表引擎進行了詳細的測試。」
- 後:「報表引擎仔細測過了。」

**4b 名詞化「性/度/化」堆疊。**〔高,余光中/學術論文〕 抽象名詞成災是英式中文首要症狀 → 還原成動詞或形容詞。半機掃:grep「性」「度」結尾詞密度。
- 前:「系統的可靠性很高,也提升了準確度。」
- 後:「系統很可靠,算得也更準。」

**4c 「被」字被動句濫用。**〔高,余光中〕 中文天然說「戲看完了」,不說「戲被看完了」 → 改主動式或受事主語句。
- 前:「報告已被生成。」
- 後:「報告產好了。」

**4d 冗贅套件:「…之一」「成功地」「基本上」「相對而言」。**〔高,余光中:「之一」是英文 one of 的硬譯〕 → 刪或直接斷語。
- 前:「這是最重要的原因之一。」
- 後:「主要就是這個原因。」

**4e 「通過…(的方式)」→ 台灣寫「透過」。**〔中,兩岸用詞對照表 + 嚴重度分級憑觀察〕「通過」當介詞是大陸慣用,AI 常輸出「通過分析…我們可以…」,雙重露餡(大陸介詞 + 機制腔)。機掃:grep「通過」逐一人判(「考試通過」「議案通過」合法,不是這條要改的)。
- 前:「通過分析趨勢,我們可以得出結論。」
- 後:「趨勢一看,結論很清楚。」

## 層 5 — 標點排版 house style(新增層;全部可機掃)

2026-07-26 user 拍板為硬規則,不是建議。**適用範圍:中文散文與對外文案(建造日誌、社群貼文、產品頁、報告客戶可見段)。程式碼、CSS、網址、檔案路徑、指令、JSON/設定檔裡的半形符號不適用,不要拿這層去改 code。**

**5a 中文段落一律全形標點,禁止彎引號。**〔高,教育部《重訂標點符號手冊》+ 出版社體例;〔機掃〕〕
- 逗號 `,`→`，`、句號 `.`→`。`、頓號用「、」、冒號 `:`→`：`、分號 `;`→`；`、問號 `?`→`？`、驚嘆號 `!`→`！`、括號 `()`→`（）`。
- **禁止彎引號 “ ” ‘ ’(U+201C/U+201D/U+2018/U+2019)**——這是大陸與英文用法,AI 極常輸出,grep 到彎引號幾乎可直接判定沒過台灣校對,是全報告成本最低、最準的一條檢查。
- **例外一:直引號 `"`(U+0022),前後同一個字元。** user 選的是直引號不是彎引號,這條例外不解除、不要「順手」改成彎引號。
- **例外二:半形空白。** 中英文之間、中文與數字之間可以加空格(例如「完整報告 NT$499」),這是合法用法,不算違規半形標點。
- 機掃:grep `[“”‘’]`(彎引號/彎單引號)→ 一律零命中才算過。

**5b 刪節號用「……」(全形六點),不用「...」(半形三點)。**〔高,教育部手冊〕 半形三點是英文習慣,AI 高頻輸出。機掃:grep `\.\.\.`(排除網址/程式碼上下文)。

**5c 破折號依場景分級,見層 1h。**〔中,符號本身合法〔高〕,頻率敏感度〔中,調研觀感〕〕 社群貼文零使用,長文全篇最多一處。機掃:grep「——」計數。

**5d 阿拉伯數字與英文字母用半形。**〔高,出版社體例/政府文書慣例〕 中文全形、數字外文半形一致。

**5e 中英文之間空格:已拍板,加半形空格。**〔中,GitHub 中文文案排版指北一派;另一派「台灣媒體多不加」為調研觀察非官方裁定,但 user 已擇一,以此為準,不必逐案重新辯論〕 全文一致,可機掃混用(同一篇裡「NT$499」和「NT$ 499」同時出現算違規)。

**5f 驚嘆號一篇最多一個,問號不連用。**〔低,憑觀察無來源,拿不準時人工裁量,不當鐵律〕 台灣商業文案的驚嘆號密度明顯低於大陸電商腔,方向可信但無法引證,標記供參不強制。

## 層 6 — 場景 profile(不同用途語氣不同)

| 場景 | 語氣鎖定 | 額外規則 |
|---|---|---|
| 建造日誌 | 第一人稱工程敘事,可自嘲 | 講做了什麼+踩了什麼雷;數字要真;破折號限一(層 1h) |
| Landing / 漏斗 | 短句、斷語、零 hedge | 每個 claim 另做逐條查證;破折號歸零 |
| 社群貼文(FB/IG/Threads) | 最口語,允許不完整句 | 不推銷;破折號歸零;不用「首先/其次」(層 1i) |
| 報告客戶可見段 | 專業但不端著 | 斷語不機制;不用恐嚇話術逼人下單;口語粒子(欸/啦)不用 |

## 層 7 — 產出格式

改完輸出:
1. **前 / 後對照**,逐條標砍了哪些 tell(例:「砍 1b 反義句、2b 大概率→八成、4a 進行了測試→測過了、5a 彎引號→直引號」)。
2. **三條硬檢查**(取代同模型自評的分數):
   - (1) 有沒有新增原文沒有的事實?(層 0a)
   - (2) 詞表黑名單(層 2a/2b)+ 標點(層 5a/5b/5c)grep 一次,零命中?
   - (3) 念一遍測試通過?(層 3d)
3. **可機掃規則清單**(供未來考慮做成 pre-commit/hook,目前仍人工執行):
   - 彎引號 `[“”‘’]` 零命中(層 5a)
   - 半形刪節號 `\.\.\.` 零命中(層 5b,排除網址/程式碼路徑)
   - 「——」計數依場景上限(層 1h/5c)
   - 「不是.{2,12},而是」「不僅…更」零命中或人工核可(層 1b)
   - 句首「其實,」+ 段落內無具體名詞/數字 → 人工核可(層 3b,無法純機掃,需語意判斷)
   - 中國用語一級表(層 2b)零命中

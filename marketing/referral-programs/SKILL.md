# referral-programs — 推薦迴圈設計

改造自 coreyhaines31/marketingskills 的 `referrals`(MIT license)。核心差異:不是從零設計計畫,而是補「迴圈的觸發 / 分享 / 誘因 / 追蹤」設計。砍掉大規模 affiliate 招募與付費佣金結構(YAGNI + 早期階段,且涉金流 / 稅務要先過法遵)。開工前讀專案自己的 product-marketing context 文件。

## 現況(先對齊)

先確認專案目前有沒有歸屬機制(例如 `?ref` 參數、邀請碼),能不能追到「誰分享、誰經由誰進來」。沒有就先補歸屬再談誘因;有就沿用,不重做。

成敗看專案定位文件定義的北極星指標:帶進來的人有沒有往付費 / 成交走,不只看分享數。

## 推薦迴圈四要素

1. **觸發時機(trigger moment)**:在使用者拿到價值的「爽點」請他分享——領完免費結果、完成一次有感的體驗。**不要**在付款頁或還沒獲得價值時就逼分享。
2. **分享機制**:一鍵帶歸屬參數的連結 / 圖卡。摩擦越低越好,IG / Threads / LINE 分享優先(台灣)。
3. **誘因**:早期優先**非金錢誘因**——解鎖一次額外體驗、多一次免費額度、進階內容。金錢 / 佣金誘因先擱置(涉金流結算 + 稅務門檻 + 發票,先過專案法遵 review)。
4. **成效追蹤**:靠歸屬參數追 分享數 -> 點擊 -> 註冊 -> 成交 的漏斗,看每一段掉在哪。

## 誘因設計守的線

- **不恐嚇**:分享話術是「這個我覺得你會有感」,不是「不分享就拿不到 / 會倒楣」。
- **內容夠好才會被分享**:分享標的(圖卡 / 摘要)要真的值得截圖傳給朋友。
- **個資 / 本人限定**:分享的是「工具 / showcase」層,不是把別人的個人資料外流;遵守專案的隱私設定。
- **防外流**:對外分享素材視需要沿用浮水印策略(截圖擋不了,只能溯源)。

## 誘因誠實紅線

- 承諾的獎勵必須真的發得出來(不宣稱未實作的回饋機制)。
- 不寫死金額 / 折扣數字(系統動態)。
- 供應商保密規則依專案政策。

## 收尾

分享文案 / 邀請頁定稿前過 `de-ai-tone` + 專案自己的 claim 逐條查證流程。跟 `free-tools-growth`(工具當分享標的)、`social-media`(分享話術)串起來。要動金錢誘因 / 佣金前先過專案的法遵 / 財務 review。

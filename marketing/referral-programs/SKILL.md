# referral-programs — 推薦迴圈設計

改造自 coreyhaines31/marketingskills 的 `referrals`(MIT license)。核心差異:本專案**?ref 歸屬機制已經建好**,這支不是從零設計計畫,而是補「迴圈的觸發 / 分享 / 誘因 / 追蹤」設計。砍掉大規模 affiliate 招募與付費佣金結構(YAGNI + pre-revenue,且涉金流 / 稅務要先過法遵)。開工前讀 `docs/strategy/PRODUCT_MARKETING_CONTEXT.md`。

## 現況(先對齊)

- `?ref` 歸屬已 live(免費八字論X 漏斗),能追到誰分享、誰經由誰進來。
- 北極星=歸屬預約。推薦迴圈的成敗看「帶進來的人有沒有往預約 / 付費走」,不只看分享數。

## 推薦迴圈四要素

1. **觸發時機(trigger moment)**:在使用者拿到價值的「爽點」請他分享——領完免費報告、抽完每日一牌、看完一段讓他有共鳴的解讀。**不要**在付款頁或還沒獲得價值時就逼分享。
2. **分享機制**:一鍵帶 `?ref` 的連結 / 圖卡(每日一牌、命盤摘要卡)。摩擦越低越好,IG / Threads / LINE 分享優先(台灣)。
3. **誘因**:pre-revenue 期優先**非金錢誘因**——解鎖一次額外解讀、多一次免費抽卡、進階內容。金錢 / 佣金誘因先擱置(涉金流結算 + 稅務門檻 + 發票,要先過法遵,見 `dev-rule/LEGAL_COMPLIANCE.md`)。
4. **成效追蹤**:靠 `?ref` 追 分享數 → 點擊 → 註冊 → 預約 的漏斗,看每一段掉在哪。

## 命理語境的誘因設計(守紅線)

- **賦權非恐嚇**:分享話術是「這個解讀我覺得你會有感」,不是「不分享解鎖不了你的凶運」。
- **內容夠好才會被分享**:護城河在判斷 / 辯證層的解讀品質;分享標的(圖卡 / 摘要)要真的值得截圖傳給朋友。
- **個資 / 本人限定**:免費報告內容嚴格本人,分享的是「工具 / showcase」層,不是把別人命盤外流。命盤分享走 `shareBirthInfo` 隱私設定。
- **防外流**:對外分享圖卡沿用報告浮水印 / 盲印策略(截圖擋不了,只能溯源)。

## 分享標的(本專案現成的)

- 每日一牌 Canva 圖卡(病毒獲客,天生可分享)
- 金錢卦 showcase 擲幣結果
- 占星曆換座 / 逆行提醒
- 命盤摘要卡(帶浮水印)

## 誘因誠實紅線

- 承諾的獎勵必須真的發得出來(不宣稱未實作的回饋機制)。
- 不寫死金額 / 折扣數字(後台動態)。
- 供應商講「AI」。
